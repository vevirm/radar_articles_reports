# V17.13.33 — curator candidate testing + snowball reliability

This repository is based on the uploaded V17.13.32 lean release, with the uploaded `radar (41).json` used as the current `radar.json` state.

## Round XIV candidate testing

- `curation/EU_RI_Relevant_Papers_Round_XIV.docx` is retained as the curator source document.
- `curator_candidate_tests.json` turns the 17 curator groups into 26 independently testable works. Bundled `And:` / `With:` works are split so a relevant companion cannot be lost just because the first paper in a cluster is weaker for the radar.
- DOI-supplied works are resolved by exact DOI. Companion works without a supplied DOI are resolved by exact-title Crossref search, then OpenAlex fallback.
- Curator notes and row hints are **not evidence** and do not bypass the existing A/B gates. Source-derived metadata/abstract text must pass normal quality, English, date, EU relevance, R&I substance, and strategic-context rules.
- Passing A/B candidates rejoin the ordinary scholarly pool. Admitted Strand-A evidence is then classified by the exact browser Sovereignty Frontier classifier.
- The scanner writes `curator_candidate_testing` into `radar.json`, including per-candidate status, published strand, and actual `matrix_cell` when the browser classifier places it.
- The W25 source date (28 April 2026) is deliberately left to the scanner's retention-window check; it is not forced inside the corpus.

## Citation snowball reliability

- The scanner now uses `OPENALEX_API_KEY` when the workflow secret exists. V17.13.32 passed the secret into the job but the Python scanner ignored it.
- Anonymous operation still works when no key is configured.
- Seed-resolution and anchor-fetch HTTP 429s now produce explicit `citation_snowball.status = "blocked_openalex_429"` and `rate_limited = true` rather than a silent `0 / 20` result.

## Regression tests

`tests/test_scanner_features.py` covers:

- all 17 Round XIV groups / 26 individual works;
- no curator hint pre-populates authoritative matrix fields;
- candidate admission tagging and browser-Matrix placement reporting;
- optional OpenAlex API-key request injection without persistence;
- explicit snowball 429 status;
- Matrix bridge placement output.

The GitHub Actions scan workflow runs these tests before every due scan.

Run locally:

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
python scripts/build_release.py --root .
```
